# Methodology

## Purpose

Professional reframing translates the *meaning* of work into language that a target professional audience can recognize. It is not a synonym-replacement exercise.

Use this sequence:

1. **Evidence** - what literally happened?
2. **Business function** - what organizational function did that action serve?
3. **Impact** - why did it matter?
4. **Relevance** - which supported aspects matter to this audience?
5. **Voice** - how can this be expressed clearly, concisely, and naturally?

## Meaning-preserving transformation

A good reframe may:
- clarify the organizational function;
- make the actor and action explicit;
- identify the stakeholder when known;
- replace internal/local wording with broadly recognized terminology;
- surface a verified result;
- reorder information so the most relevant point appears first;
- compress repetitive context.

A good reframe may not:
- create new authority;
- create new scale;
- create new accomplishments;
- create new metrics;
- create expertise;
- create people-management responsibility;
- imply causation where only participation is established.

## Example

Source:
"People from different teams came to me when they had trouble with the database, and I showed new staff how to use it."

Evidence:
- recurring database support;
- multiple teams;
- troubleshooting;
- new-staff instruction.

Supported functions:
- cross-functional system support;
- issue resolution;
- user training/onboarding support.

Professional reframe:
"Provided cross-functional database support, resolving user issues and training new employees on day-to-day system use."

Not justified without more evidence:
- enterprise system ownership;
- change-management leadership;
- database administration;
- organizational transformation.
